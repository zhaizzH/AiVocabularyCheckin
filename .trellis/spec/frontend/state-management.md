# 状态管理

> 本项目前端状态的管理方式。

---

## 概览

**保持灵活，不指定统一状态库**（团队决定）。按平台使用各自的最小默认方案：

- **小程序端**：页面状态用 `data` + `setData`；跨页面共享的少量全局状态
  （当前用户、已选词库、token）用 `globalData` + `wx.Storage` 持久化。
- **管理端（React）**：组件内状态用 `useState`；少量跨组件状态用
  `useContext`。仅当某个功能确实出现层层 prop 传递时，才允许引入轻量库
  （如 Zustand）——引入前需在任务 PRD 中说明理由。

---

## 状态分类

| 类别 | 示例 | 放置位置 |
|------|------|----------|
| 组件/页面本地状态 | 表单输入、弹窗开关 | `useState` / 页面 `data` |
| 全局客户端状态 | 当前用户、token、已选词库 | React Context / 小程序 `globalData` + `Storage` |
| 服务端数据 | 词库列表、打卡记录、错题 | 组件内请求状态（见 hooks 规范），不入全局 |
| URL 状态 | 管理端列表页码、筛选条件 | React Router 的 search params |

---

## 什么时候才用全局状态

只有同时满足以下两条，才允许提升到全局（Context / globalData）：

1. 3 个以上互不嵌套的页面/组件需要读同一份数据；
2. 数据变化需要跨页面同步（如切换词库后，学习页和统计页都要变）。

否则一律留在本地——全局状态越少，两端代码越好追踪。

---

## 服务端状态

- 服务端数据**不放进全局状态**，不自己做缓存层；每次进入页面按需请求。
- token 是唯一持久化的鉴权状态：小程序存 `wx.Storage`，管理端存
  `localStorage`；两处都由 `utils/request` 统一读取和注入请求头。
- 401 响应时由 `utils/request` 统一清除 token 并跳转登录页——页面不各自
  处理登出逻辑。

---

## 常见错误

- 把从接口拿到的列表塞进全局 Context"备用"——服务端数据入全局是状态
  不同步 Bug 的主要来源。
- 小程序页面间靠 `Storage` 传临时数据——`Storage` 只放需要持久化的
  状态（token、已选词库 id）；页面间临时传参用 URL 参数或
  `EventChannel`。
- Context 里放一个"超级大对象"导致每次变更全树重渲染——按职责拆多个
  Context，或保持状态本地。
