## Goal

依据 `docs/` 下已冻结的 S2《软件需求规格说明书》、S3《软件概要设计说明书》、《接口详细设计》（契约冻结版）与《需求清单-功能与规则》，实现可运行、可联调、可演示的四端系统，形成 S4「程序包」交付物（代码 + 数据库脚本 + 安装部署说明）。

## 范围

### 交付物一：`backend/` — Spring Boot 业务后端（P0，第一个做的）

- 技术栈：Java 17 语法级别 + Spring Boot 3.x + MyBatis-Plus + MySQL 8 + JWT + BCrypt。
- 数据库：7 张表 SQL 迁移脚本（S3 的 6 张 + 决策新增的 `word_progress`），存放 `src/main/resources/db/`。
- 接口：**30 个对外接口全部实现**（认证 5 / 词库 4 / 学习 4 / 复习 2 / 错题 3 / AI 3 / 统计 2 / 管理 7 → 补齐缺口后为 10），加 3 个内部 AI 接口的**调用方**。
- AI 降级：ai-service 不可用时，例句接口返回内置例句 + `degraded:true`；讲解/报告返回 5001/5002。
- 种子词库：三本词书（四级/六级/考研）真实导入，共 22761 词。

### 交付物二：`ai-service/` — FastAPI AI 微服务（P1）

- 技术栈：Python 3.10+ / FastAPI / LangChain / DeepSeek。
- 3 个接口：`/ai/v1/example`（15s）、`/ai/v1/explain`（30s）、`/ai/v1/report`（60s）。
- **硬约束：不连接任何数据库**（架构一等约束，来自 S3 §3.1）。
- 密钥仅从环境变量读取。

### 交付物三：`miniprogram/` — 微信原生小程序 学生端（P1）

- F1 登录/注册 → F10 我的，共 10 个功能模块。
- 六 tabBar：首页 / 学习 / 复习 / 错题 / 统计 / 我的。
- 统一 `utils/request`（baseURL、token 注入、`code !== "0"` 处理、401 清 token 跳登录）。
- AI 三件套必须有加载态 + 超时 + 降级文案；所有提交按钮防重复。

### 交付物四：`frontend/` — React 管理端（P2）

- React 18 + TypeScript + Vite + Ant Design 5。
- 页面：登录、词库管理（列表/导入/单词 CRUD 弹窗）、用户管理（搜索/禁用启用）、系统监控。

### 交付物五：交付文档（P2，随开发产出）

- S4 安装部署说明（含数据库脚本执行步骤、环境变量清单）。
- 补充 S5 测试用例集所需的可运行系统前提。

## 跨子任务验收标准

以下标准必须在父任务层面成立，不能靠单个子任务自说自话：

### A. 契约一致性

- [ ] 实际实现的所有接口路径、请求字段、响应字段、错误码**逐项对照** `docs/接口详细设计.md`，无偏差。
- [ ] 3.2 节决策的三处契约缺口（`GET /api/admin/books`、`DELETE /api/admin/books/{bookId}`、`GET /api/admin/monitor/ai-stats`）已**先回写文档**（含第 10 章变更记录），再在代码中实现。
- [ ] 复习进度新增 `word_progress` 表的偏离已在 design.md 记录，并同步至 S3 修订说明。

### B. 响应包装与错误码

- [ ] 所有接口返回 `{ code, message, data }`，成功 `code: "0"`；**业务失败 HTTP 状态仍为 200**。
- [ ] 错误码严格分段：1xxx 认证 / 2xxx 词库 / 3xxx 学习打卡 / 4xxx 错题 / 5xxx AI / 9xxx 系统；已分配码值不得改语义。
- [ ] 401 仅用于 token 缺失/过期/账号禁用；403 用于非管理员访问 `/api/admin/**`；500 仅用于未预期崩溃。

### C. AI 降级（一等约束）

- [ ] **在 ai-service 完全不启动的情况下**，backend 的 `/api/client/ai/example` 返回 `code:"0"` + `degraded:true` + 内置例句，前端不报错。
- [ ] 在同样条件下，`/api/client/ai/explain` 与 `/api/client/ai/report` 返回 5001/5002，前端展示可读文案且**不影响**「标记已掌握」等业务动作。
- [ ] 学习、打卡、复习三条核心链路**不依赖**任何 AI 调用成功。
- [ ] 降级事件被记录（日志 WARN + 内存计数器），可通过 `GET /api/admin/monitor/ai-stats` 观测。

### D. 鉴权与安全

- [ ] 密码 BCrypt 入库，日志中**绝不出现**密码、token、AI key。
- [ ] 禁用用户即时生效：禁用后其 JWT 下次校验返回 401 / 1003 文案。
- [ ] 不允许禁用 ADMIN 账号（返回 1005）。
- [ ] `.env` / `application-local.yml` 等含密钥的文件已被 `.gitignore` 排除，仓库内只有占位符。
- [ ] `ai-service/` 中**不存在**任何数据库连接代码（用 grep 验证）。

### E. 数据正确性

- [ ] 三本词书 `word_count` 与实际 `word` 表行数一致（7508 / 5651 / 9602）。
- [ ] 间隔复习算法：答对 stage+1 且封顶 4；答错 stage 重置为 1、`wrong_count`+1、确保收录错题本；`next_review_date` 按 1/3/7/15 天推进。
- [ ] 打卡幂等：同日重复打卡返回 3001，不重复写入。
- [ ] 连续天数：上次打卡为昨天 → +1；否则重置为 1。

### F. 端到端可演示

- [ ] 一条完整链路走通：注册 → 选词书 → 学 20 词（含点「不认识」）→ 打卡 → 错题本看到错题 → 复习页看到该词（答错退回第 1 阶段）→ 统计页出现热力图数据。
- [ ] 管理端可完成：导入词书（JSONL）→ 看到词书列表 → 单词增删改查 → 禁用某用户 → 该用户登录被拒。
- [ ] 以上链路在 `ai-service` 宕机时，除 AI 相关功能外**全部仍然可用**。

## 验收方式

1. **接口层**：backend 提供一份可执行的接口自测清单（curl / HTTP 脚本），逐条跑通并留存输出。
2. **数据库层**：通过 DBX MCP 直接查表验证种子数据、`word_progress` 状态推进、错题计数。
3. **降级层**：手动停掉 ai-service 进程，重跑 AI 三个接口，核对降级响应。
4. **前端层**：小程序用微信开发者工具真机/模拟器验证 F1–F10；管理端 `npm run dev` 浏览器验证。
5. **一致性**：对照契约文档逐字段 diff，任何偏差须先改文档。
