## P3 项目简介

- 一句话：面向大学生的 AI 辅助背单词平台——**学（词库+每日计划）→ 练（打卡+复习）→ 复盘（错题+AI 报告）** 完整闭环
- 痛点切入：传统背单词工具「重词库、轻辅导」，错题没人讲、效果没反馈
- AI 增强三件套：AI 例句生成 / AI 错题讲解 / AI 学习报告

## P4 系统架构（重点页）

放架构图：双前端（微信小程序 + React 管理端）→ Spring Boot 业务后端（唯一连库）→ MySQL；业务后端 → FastAPI AI 微服务（无状态）→ DeepSeek 大模型。

演讲要点：
- **业务与 AI 解耦**：AI 服务独立部署、不连数据库
- **降级是一等设计约束**：AI 挂了，核心学习功能照常

## P5 关键技术选型与理由

| 技术 | 用在哪 | 为什么 |
|---|---|---|
| Spring Boot 3 + MyBatis-Plus | 业务后端 | 生态成熟，CRUD 与分页高效 |
| FastAPI + LangChain 1.x + LangGraph | AI 微服务 | LangChain 编排提示词；LangGraph 实现学习报告「整理→分析→生成」多步链路（含条件路由：数据不足时跳过两次 LLM 调用） |
| 微信原生小程序 | 学生端 | 零第三方库，性能可控 |
| React 18 + TS + AntD 5 | 管理端 | 组件成熟，类型安全 |

## P6 三个核心设计决策（差异化亮点）

1. **契约先行**：接口详细设计冻结后才写代码，统一 `{code,message,data}` 包装、错误码分段（1xxx–9xxx），前后端并行开发零扯皮
2. **AI 降级设计**：自控超时（12/25/50s）严格小于后端超时（15/30/60s）；例句降级到内置例句，讲解/报告给可读提示
3. **间隔复习算法**：1/3/7/15 天四阶段，答对升阶段、答错退回起点并计错题

## P7 现场演示（3 分钟脚本）

1. 小程序：微信登录 → 选词书 → 学 3 个词（故意点 1 个「不认识」）→ 打卡（展示连续天数）
2. 错题本 → AI 讲解（真实大模型生成，实测约 3.5s）
3. **拔网线环节**：停掉 AI 服务 → 再点 AI 例句（黄条降级提示 + 内置例句）→ 学习/打卡照常 → 重启恢复
4. 管理端：导入词书 JSONL（预览→导入→「成功 N 条跳过 M 条」）→ 禁用某用户 → 切回小程序看该用户被踢出

（备注：演示前把 ai-service 重启一遍确认 key 有效；准备降级演示用的命令行窗口）

## P9 遇到的挑战（真实踩坑 3 个）

1. 微信小程序 tabBar 硬上限 5 项 → 统计页改普通页（平台限制驱动设计调整）
2. 管理端 React 无限重渲染白屏 → `useSyncExternalStore` 快照必须是稳定引用（只有真实浏览器 E2E 能抓到）
3. DeepSeek 模型名退役 + thinking 模式与 JSON 输出冲突 → 模型名环境变量化 + 显式关闭 thinking + JSON mode 双保险
