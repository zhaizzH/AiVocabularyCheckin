# 学生端（微信小程序）需求分析与原型设计

> 范围：仅学生端（miniprogram/）。管理端见 admin-prototype.html 与需求清单第 6 章。
> 每个功能包含：功能目标 / 前置条件 / 主流程 / 界面元素清单 / 状态设计 / 接口依赖 / 边界与校验。
> 原型文件：`prototype/miniprogram-prototype.html`（正常流程）、`prototype/miniprogram-states.html`（状态变体）。
> 版本：V1.0 · 2026-10-16

## F1 登录 / 注册

**功能目标**：让用户以最低成本建立账号并进入学习闭环。

**前置条件**：无（唯一两个免 JWT 页面）。

**主流程**：
0. 页面顶部为「微信一键登录」主按钮（学生端主入口）：`wx.login` 拿 code → `POST /api/client/auth/wx-login` → 成功存 token + userInfo → `isNewUser=true` 时跳「设置昵称」引导页（填昵称 + 选内置头像）→ 首页
1. 下方「账号密码登录/注册」为备用入口，折叠展开表单；底部链接切换注册态（增加「确认密码」字段）
2. 登录：前端校验非空 → `POST /api/client/auth/login` → 成功存 token + userInfo 到 Storage → 跳首页
3. 注册：前端校验格式（用户名 4–20 位、密码 ≥6 位含字母+数字、两次一致）→ `POST /api/client/auth/register` → 成功自动调登录 → 跳首页

**界面元素清单**：

| 元素 | 规格 |
|---|---|
| Logo 区 | 产品名 + slogan「学—练—复盘」 |
| 用户名输入框 | placeholder「用户名（4-20位）」 |
| 密码输入框 | password 类型 |
| 确认密码框 | 仅注册态显示 |
| 主按钮 | 登录 / 注册，提交中显示 loading 防重复点击 |
| 切换链接 | 「没有账号？去注册」/「已有账号？去登录」 |

**状态设计**：
- 失败：toast 显示后端 message（1001 用户名占用 / 1002 密码错误 / 1003 账号禁用）
- 网络失败：toast「网络异常，请检查网络后重试」

**接口依赖**：`POST /api/client/auth/register`、`POST /api/client/auth/login`、`POST /api/client/auth/wx-login`

**边界与校验**：格式错误前端就地提示不发请求；微信登录失败 → 1004 toast「微信登录失败，请重试或使用账号密码登录」；不做找回密码（写进边界）；微信登录前提是已注册小程序获取 AppID（开发期用测试号）。

## F2 首页

**功能目标**：一屏回答三个问题——今天学什么、学得怎么样、下一步点哪。

**前置条件**：已登录。

**主流程**：`onShow` 时并行请求今日计划、连续打卡、词书列表 → 渲染进度卡 + 数据卡 + 词书卡。

**界面元素清单**：

| 元素 | 数据来源 | 规格 |
|---|---|---|
| 今日进度卡 | `/api/client/study/plan` | 已学/计划词数 + 进度条 + 主按钮（继续学习/开始学习/今日已完成✓） |
| 数据统计行 | `/api/client/study/streak` + plan | 连续打卡天数 / 累计已学 / 今日待复习数 |
| 我的词书卡 | `/api/client/books` | 已选词书列表（名称 + 已加入标签 + 进度 n/总数）；未选词书显示「+ 加入」 |

**状态设计**：
- **空态 A（未选词书）**：进度卡替换为引导插画 +「先去选一本词书」按钮 → 跳词库页
- **空态 B（词书学完）**：「本词书已学完🎉」+ 引导换词书
- **今日已完成**：主按钮变灰「今日已完成，明天继续」，仍允许自由复习

**接口依赖**：`GET /api/client/study/plan`、`GET /api/client/study/streak`、`GET /api/client/books`、`POST /api/client/books/{id}/select`

**边界与校验**：三接口任一失败不阻塞其他卡片；进度卡失败显示「加载失败，点击重试」。

## F3 词库浏览与选择

**功能目标**：让用户 30 秒内选到合适的词书。

**主流程**：顶部分类 Tab（全部/四级/六级/考研）→ 词书卡片列表 → 点「加入」选择词书 → toast「已加入学习计划」；已加入的可「移出」（modal 二次确认）。

**界面元素清单**：

| 元素 | 规格 |
|---|---|
| 分类 Tab | 全部 / 四级 / 六级 / 考研 |
| 词书卡片 | 词书名、分类标签、单词数、简介（2 行截断）、操作按钮（加入/已加入✓） |

**状态设计**：列表为空（管理端还没导入词书）→「词书准备中，请稍后再来看看」。

**接口依赖**：`GET /api/client/books?category=`、`POST /api/client/books/{id}/select`

**边界与校验**：可同时选多本；移出不影响历史学习记录。

## F4 每日学习（单词卡片 + 打卡）★核心页面

**功能目标**：完成当日计划词的流水线学习并打卡，形成闭环。

**前置条件**：已登录、已选词书、今日计划非空。

**主流程**：
1. 进入页面拉取 `/api/client/study/plan`，得到今日单词序列（复习词在前，新词在后）
2. 卡片正面：单词 + 英式音标；点击翻面 → 释义（词性 + 中文，多义项分条）
3. 「✓ 认识」→ 标记已学、下一张；「✗ 不认识」→ 标记已学 + 收录错题本、下一张
4. 任意时刻可点卡片上「✦ AI 例句」→ 弹出 F5 弹层
5. 全部过完 → 打卡按钮点亮 → 点击 `POST /api/client/study/checkin` → 打卡成功页（连续天数、今日词数、错题数、「查看错题」入口）

**界面元素清单**：

| 元素 | 规格 |
|---|---|
| 进度指示 | 「词书名 · 当前序号/总数」顶部常驻 |
| 单词卡片 | 正面 word+phonetic；背面 translation；翻面动画 200ms |
| AI 例句入口 | 卡片底部标签按钮 |
| 操作按钮组 | 「✗ 不认识」（描边）/「✓ 认识」（实心）等宽并排 |
| 打卡按钮 | 未达条件时灰色禁用 + 提示「完成学习后打卡（n/20）」 |

**状态设计**：
- **打卡成功态**：结果页含连续天数大数字 + streak 火苗视觉 + 分享按钮（一期可不做分享，留位）
- **重复打卡**：toast 3001「今日已打卡」，按钮变「已打卡 ✓」
- **计划为空**：引导页「今日无待学内容」+ 去复习入口

**接口依赖**：`GET /api/client/study/plan`、`POST /api/client/study/checkin`

**边界与校验**：中途退出再进入，从 plan 接口重新拉取进度（已学单词服务端已标记，不重复出现）；打卡请求需防重复提交（按钮 loading）。

## F5 AI 例句弹层

**功能目标**：用 AI 给当前单词生成例句与助记，增强记忆。

**主流程**：点「✦ AI 例句」→ 底部弹层 + 骨架屏「AI 正在生成…」→ `POST /api/client/ai/example`（超时 15s）→ 渲染例句（英文 + 中文）+ 助记块。

**界面元素清单**：弹层标题（✦ AI 例句 · 单词）、例句区、助记区（浅色底卡片）、关闭按钮。

**状态设计**：
- **加载态**：骨架屏，禁止重复点击
- **降级态**：超时/失败 → 展示词库内置例句（word.example）+ 顶部提示条「AI 暂时不可用，展示内置例句」
- 内置例句也为空 → 「该单词暂无例句」

**接口依赖**：`POST /api/client/ai/example`

**边界与校验**：降级不阻塞学习；同一单词本次会话内重复点击可复用已拉取结果（前端会话缓存）。

## F6 间隔复习

**功能目标**：按遗忘规律推送待复习单词，答错回炉。

**前置条件**：存在待复习单词（下次复习日期 ≤ 今天 且未掌握）。

**主流程**：进入复习页拉取 `GET /api/client/review/today` → 顶部显示待复习总数 → 卡片作答（先回忆，点击翻面核对）→ 选「答对/答错」→ `POST /api/client/review/record` → 下一张；全部完成 → 「今日复习完成」页。

**界面元素清单**：待复习计数卡、复习卡片（同学习卡片样式）、答错/答对按钮组（按钮上注明后果：「退回1天后」「进入下一阶段」）。

**状态设计**：
- **空态**：「今日没有待复习内容🎉」+ 去学习新词入口
- 复习完成的单词实时从列表移除

**接口依赖**：`GET /api/client/review/today`、`POST /api/client/review/record`

**边界与校验**：算法规则——间隔序列 1/3/7/15 天；答对升阶段，答错降回第 1 阶段且 wrong_count+1、保持/收录进错题本。

## F7 错题本（含 AI 讲解）

**功能目标**：集中管理薄弱单词，配合 AI 讲解攻克。

**主流程**：筛选 Tab（未掌握/已掌握）→ 错题列表（分页）→ 每条操作：「✦ AI 讲解」展开讲解区 /「标记已掌握」/「移除」（modal 确认）。

**界面元素清单**：

| 元素 | 规格 |
|---|---|
| 筛选 Tab | 未掌握（默认，带数量角标）/ 已掌握 |
| 错题条目 | 单词、释义（1 行截断）、错误次数 + 来源标签、三个操作 |
| 讲解区 | 条目内展开：讲解文本 + 学习建议 + 「标记已掌握」按钮 |

**状态设计**：
- **AI 讲解加载**：讲解区骨架屏，超时 30s
- **AI 讲解失败**：「AI 讲解暂时不可用，请稍后再试」，标记已掌握按钮仍可用
- **空态**：「太棒了，错题本空空如也」+ 去学习入口

**接口依赖**：`GET /api/client/mistakes?mastered=&page=`、`POST /api/client/ai/explain`、`POST /api/client/mistakes/{id}/mastered`、`DELETE /api/client/mistakes/{id}`

**边界与校验**：同一单词重复答错只累加 wrong_count 不重复建条目；移除为逻辑删除。

## F8 AI 学习报告

**功能目标**：周期性复盘，让 AI 基于真实数据给出学习分析。

**入口**：「我的」页 → AI 学习报告。

**主流程**：点击进入 → `POST /api/client/ai/report`（超时 60s，全屏 loading「AI 正在分析你的学习数据…」）→ 分段渲染报告：学习概况 / 薄弱环节 / 学习建议。

**状态设计**：
- **数据不足**：学习天数 < 3 → 直接展示「数据还太少，学几天再来生成报告」（不调 AI）
- **失败**：「报告生成失败，请稍后重试」+ 重试按钮
- 报告每次实时生成，不缓存

**接口依赖**：`POST /api/client/ai/report`

## F9 数据统计

**功能目标**：用可视化给坚持正反馈。

**界面元素清单**：

| 元素 | 规格 |
|---|---|
| 打卡热力图 | 近 12 周日历格，4 档色阶（0 / 1–10 / 11–20 / 21+ 词），点击格子 toast 显示当日词数 |
| 掌握度曲线 | 近 30 天双折线：掌握度%（实线）+ 每日错题数（虚线） |

**状态设计**：无任何学习数据 → 「开始第一次学习后，这里会长出你的数据」。

**接口依赖**：`GET /api/client/stats/heatmap`、`GET /api/client/stats/mastery`

**边界与校验**：聚合在 SQL 完成；热力图点击仅为展示，无跳转。

## F10 我的 / 个人信息

**界面元素清单**：

| 元素 | 规格 |
|---|---|
| 用户卡 | 头像 + 昵称 + @用户名 + 注册时间 + 累计打卡天数 |
| 功能列表 | 我的词书管理 / 更换头像（6 个内置）/ ✦ AI 学习报告 / 关于 |
| 退出登录 | 红色描边按钮，modal 确认后清 token 跳登录页 |

**规则**：昵称 ≤20 字即时保存；头像为内置 6 选 1（网格弹层）；「关于」页含版本号 + 词库版权说明（BSD 3-Clause，KyleBing/english-vocabulary）。

**接口依赖**：`GET /api/client/auth/profile`、`PUT /api/client/auth/profile`

## 全局设计规则（学生端）

1. **tabBar**：首页 / 学习 / 复习 / 错题 / 统计 / 我的 六个入口（复习与错题若有待办显示角标）
2. **刷新策略**：时效数据（进度、打卡状态、错题数）`onShow` 刷新；一次性数据（词书详情）`onLoad`
3. **401 处理**：request 封装统一清 token、跳登录页、toast「登录已过期」
4. **AI 三件套**：凡 AI 操作必有加载态、超时上限（15/30/60s）、降级文案
5. **防重复**：所有提交按钮在请求期间 loading 禁用
6. **尺寸适配**：rpx 单位，可点击元素 ≥ 88rpx 高
