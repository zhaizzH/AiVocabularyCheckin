**1 项目提出**

**1.1 项目简介**

本项目是面向大学生英语学习场景的AI辅助背单词平台，包含微信小程序端（原生框架）和网页管理端（React 18 + TypeScript + Vite + Ant Design 5）两个前端。系统以传统单词学习功能为核心（词库浏览、每日学习计划、打卡、错题本、间隔复习），以大模型AI能力为增强（AI例句生成、AI错题讲解、AI学习报告），形成“学—练—复盘”的完整闭环。系统采用Spring
Boot 3.x + MyBatis-Plus + MySQL作为业务后端，采用FastAPI +
LangChain作为AI微服务，实现业务功能与AI功能的解耦，保证系统在AI服务异常时核心功能仍可正常使用。系统采用JWT鉴权、BCrypt密码存储，前后端接口统一响应包装结构（code/message/data），契约先行、前后端并行开发。

**1.2 项目背景**

英语四六级、考研是当代大学生的刚性需求，背单词是英语学习的基础环节。然而现有的背单词工具普遍存在“重词库、轻辅导”的问题：单词只管展示和打卡，遇到错题无人讲解、学习效果无反馈、复习缺少个性化安排，学习者难以坚持。与此同时，大模型技术的成熟使得“AI个性化辅导”成为可能，可以通过生成式AI为每个学习者提供例句、错题讲解和学习报告。本小组基于上述实际需求，结合课程教学要求，设计开发了基于Spring
Boot和LangChain的AI单词学习打卡系统，用AI补足传统背单词工具的“辅导”空白，帮助大学生更高效地完成英语学习任务。

**1.3 系统边界**

本系统的服务对象为在校大学生（普通用户）与系统管理员两类角色。普通用户通过微信小程序或网页管理端完成账号注册登录、词库选择、每日学习与打卡、错题整理与复习、AI例句查询、AI错题讲解、AI学习报告生成与个人学习数据统计等功能；管理员通过网页管理端完成词库与单词数据的导入维护、用户管理、系统运行状态监控等功能。系统边界之外（明确不做）的内容包括：商品支付与交易功能、用户社交功能、真人教师辅导功能以及完整的商业化运营功能。

**3 风险评估和规避**

**3.1 技术风险**

\(1\) 大模型API不稳定或限流，可能导致AI功能不可用；  
(2) 双后端（Spring Boot +
FastAPI）架构集成复杂度较高，接口对接易出错；  
(3) LangChain版本迭代快，部分组件用法变化；  
(4) 部分技术（LangChain编排、小程序云开发）团队尚未完全掌握。

解决：(1)
后端增加缓存与降级策略，AI服务异常时核心学习功能照常可用；明确AI接口数量并收敛为3-4个（已在概要设计中固化为例句生成、错题讲解、学习报告3个接口）；(2)
先定接口契约文档，前后端按契约并行开发（接口契约已在《软件概要设计说明书》第4章细化：统一响应包装、错误码分段、REST接口表）；(3)
锁定LangChain稳定版本并统一环境；(4)
通过GitHub、B站、官方文档学习，必要时询问老师或同学。

\(5\) 双前端技术栈差异较大：小程序端为微信原生框架，管理端为React + TypeScript，两端网络层、状态管理、UI组件模式均不同，前端工作量与联调成本增加。

解决：(5)
两端共用同一份接口契约与错误码词汇表，网络请求统一收敛在各自的services/request封装层；管理端复用Ant Design组件降低开发量。

**3.2 管理风险**

\(1\) 项目进度滞后，目标不能很好地确定；(2)
个人任务不能按时完成，任务分配不合理。

解决：(1) 相互之间讨论技术实现、项目进度和功能调整；(2)
定期汇报每个人的任务完成情况，讨论后根据个人特长自主选择所负责的部分，提高整体效率。

**3.3 其他风险**

\(1\)
团队成员Java与Python开发环境、依赖包版本不一致，整合时容易出现问题；(2)
词库数据来源的版权问题。

解决：(1) 统一开发环境与依赖版本，制定规范后再进行整合；(2)
采用开源词库数据，并在文档中注明数据来源。
