**1 导言**

**1.1 编写目的**

在当今信息化与人工智能快速发展的时代，英语学习工具也在经历智能化转型。传统的背单词应用只解决“单词展示与打卡”问题，无法为学习者提供个性化辅导。本项目结合大模型技术，设计开发了AI单词学习打卡系统，用AI为每个学习者生成例句、讲解错题、输出学习报告，弥补传统工具的辅导空白。

本文档的预期读者包括：1、设计开发人员；2、项目管理人员；3、测试人员；4、用户。本文档描述了AI单词学习打卡系统的功能需求与非功能需求，作为后续概要设计、详细设计、编码与测试的依据。

**1.2 项目范围**

本系统包含微信小程序端、网页管理端两个前端，以及Spring Boot业务后端、FastAPI
AI微服务两个后端。核心功能范围包括：用户注册登录、词库浏览与选择、每日学习计划、学习打卡、错题本、间隔复习、AI例句生成、AI错题讲解、AI学习报告、学习数据统计、管理员词库与用户管理。本系统不包含支付交易、社交互动、真人辅导等功能。

**2 项目介绍**

**2.1 项目背景**

四六级与考研英语是大学生普遍面临的学习任务，背单词作为基础环节耗时最长、最需要坚持。现有背单词工具同质化严重：词库大同小异、学习方式单一、错题无人讲解、缺乏个性化反馈，用户流失率高。随着大模型技术的成熟，AI可以承担“私人辅导老师”的角色，为学习者提供即时例句、错题讲解与学习报告。本小组基于这一背景开发AI单词学习打卡系统，服务大学生英语学习场景。

**2.2 项目目标**

\(1\)
提供完整的单词学习闭环：学（词库与每日计划）—练（打卡与复习）—复盘（错题本与学习报告）；(2)
通过AI增强提供个性化辅导：例句生成、错题讲解、学习报告三方面体现AI价值；(3)
双端覆盖：微信小程序端满足移动学习场景，网页管理端满足管理维护场景；(4)
系统稳定可用：AI服务故障时核心学习功能可降级运行。

**3 应用环境**

**3.1 系统运行网络环境**

系统运行于校园网及互联网环境。微信小程序端通过微信平台访问后端服务；网页管理端通过浏览器访问后端服务；后端服务部署于云服务器或本地服务器，需具备访问外网能力以调用大模型API。

**3.2 系统软硬件环境**

**4 技术需求分析**

**4.1 设计开发的方法和工具的选择**

本项目采用前后端分离的开发方法。业务后端采用Spring
Boot 3.x框架（Controller-Service-DAO三层架构，持久层使用MyBatis-Plus），AI微服务采用FastAPI框架并结合LangChain进行大模型应用编排；前端包含微信小程序原生框架（学生端）与React 18 + TypeScript + Vite + Ant Design 5（网页管理端）。系统采用JWT鉴权、BCrypt密码哈希存储，前后端接口统一返回`Result<T>`包装结构（code/message/data）。开发工具包括IntelliJ
IDEA、VS Code、微信开发者工具、Navicat等。

**4.2 环境说明**

开发环境：JDK 17、Maven、Spring Boot 3.x、MyBatis-Plus、MySQL 8.0、Python
3.10+、FastAPI、LangChain、Node.js 18+（管理端 Vite 构建）、微信开发者工具。运行环境：云服务器（或本地服务器）+
微信小程序客户端 + 浏览器客户端。

**4.3 总体结构**

系统总体结构为：微信小程序端与网页管理端 → Spring
Boot业务后端（用户、词库、打卡、错题、统计）→ MySQL数据库；Spring
Boot业务后端 → FastAPI AI微服务（AI例句、错题讲解、学习报告）→
大模型API。AI微服务不直接访问数据库，所需数据由业务后端查询后传入，保持AI服务无状态、可独立部署；业务后端是唯一连接数据库的服务。所有前后端接口返回统一包装结构`{ code, message, data }`（`code: "0"`表示成功），错误码按模块分段管理（1xxx认证/用户、2xxx词库、3xxx学习/打卡、4xxx错题、5xxx AI服务、9xxx系统）。接口设计详见《软件概要设计说明书》第4章。

**4.4 使用技术说明及可行性分析**

\(1\) Spring Boot：业界主流的Java
Web框架，生态成熟、资料丰富，配合MyBatis-Plus可高效实现标准CRUD业务与分页查询，技术上完全可行；(2)
MySQL：关系型数据库，支持本项目三张核心表（用户表、词书/单词表、学习记录表）及其多对多关系，数据库脚本可直接导出，满足课设对“数据库脚本”的要求；(3)
FastAPI：轻量高效的Python
Web框架，与LangChain生态天然契合，适合作为AI微服务；(4)
LangChain：主流的大模型应用开发框架，用于提示词模板、多步Chain编排（学习报告生成），使AI功能结构化、可维护；(5)
微信小程序：生态完善、开发门槛低，适合校园场景的移动端应用；(6)
React 18 + TypeScript + Vite + Ant Design
5：主流的企业级管理端技术栈，组件丰富、类型安全、构建快，适合词库与用户管理场景。综上，本项目技术路线成熟可行。

**5 功能规格以及用例分析**

**5.1 功能分析**

系统功能划分为六大模块：(1) 用户模块：注册、登录、个人信息管理；(2)
词库学习模块：词库浏览与选择、每日学习计划、单词学习打卡；(3)
复习巩固模块：错题本、间隔复习提醒；(4)

数据统计模块：打卡热力图、掌握度曲线；(6)

管理员：负责词库与单词数据维护、用户管理、系统监控。

**5.4 非功能性需求**

\(1\)
界面需求：界面简洁友好，小程序端适配常见机型，操作符合移动端习惯；(2)
响应时间需求：常规页面操作响应时间不超过3秒，AI接口调用提供加载状态与超时提示；(3)
可靠性需求：AI服务异常时系统可降级运行，核心学习功能不受影响，降级时向用户展示明确的“AI暂时不可用”类提示文案；(4)
可扩展性需求：词库可通过导入扩展，AI模型可配置切换；(5)
系统安全性需求：用户密码使用BCrypt加密存储，AI接口密钥仅存于后端环境变量，接口采用JWT鉴权并做权限校验（管理端接口额外校验管理员角色）；(6)
接口一致性需求：所有前后端接口返回统一包装结构（code/message/data），业务错误通过错误码表达，前端按错误码统一处理。
